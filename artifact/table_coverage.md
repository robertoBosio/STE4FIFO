# Paper Result Coverage

This artifact focuses on the proposed STE FIFO-sizing method. Some paper results
depend on external tools or long-running flows that are intentionally not bundled
with this repository.

| Paper result | Artifact support | Notes |
| --- | --- | --- |
| Table I process/FIFO counts | Supported | `artifact/table1/run_table1.py` parses generated HLS dataflow metadata. |
| Table I latency and II | Supported | `artifact/table1/run_table1.py` runs C/RTL cosimulation on memory-interface kernels and reports average latency/II. MobileNetV2 and YOLO runs can take days. |
| Table II proposed-method FIFO sizes | Supported | Generated from the included STE models. |
| Table II generated kernel variants | Included for inspection/use | Kernels sized by the proposed method and comparison techniques are present. |
| Table II FIFOAdvisor exploration times | Not regenerated by this artifact | Requires installing FIFOAdvisor and its dependencies. |
| Table II resource utilization | Partially supported | Reviewers may run Vitis HLS synthesis on selected kernels, but full regeneration can be long and machine-dependent. |
| Table III STE vs LightningSim comparison | Not regenerated by this artifact | Requires LightningSim instrumentation and execution. |

## Rationale

The paper compares the proposed STE method with FIFOAdvisor and LightningSim-based
flows. Those tools have substantial external dependencies and version constraints.
For artifact evaluation, this repository therefore provides the core STE code and
the generated kernels, while documenting which results require external flows.
